API del Verificador de WhatsApp

Comprobá si una lista de teléfonos tiene WhatsApp. ← Volver a la app

Plan gratis

50 verificaciones por cuenta. Se descuentan solo las que se completan: un error no cuenta. Al agotarlas, la API responde 402 quota_exceeded.

Cómo funciona

Cada cuenta vincula su propio WhatsApp (como "Dispositivos vinculados"). El servicio solo escribe el número en el buscador de "Nuevo chat" y lee el resultado: nunca envía mensajes. Tu sesión se borra al cerrarla o tras 10 minutos sin uso.

  1. Creá una cuenta y guardá la API key.
  2. Abrí una sesión y escaneá el QR con tu celular.
  3. Enviá los números y consultá el resultado.

Autenticación

Enviá la clave en cada pedido: Authorization: Bearer wak_… (o X-API-Key).

1 · Crear cuenta

POST/v1/keys

curl -X POST https://TU-DOMINIO/v1/keys

{ "api_key": "wak_3f9c…", "plan": "free", "limit": 50, "used": 0, "remaining": 50 }

2 · Abrir sesión y obtener el QR

POST/v1/session   GET/v1/session

curl -X POST https://TU-DOMINIO/v1/session -H "Authorization: Bearer $KEY"
curl https://TU-DOMINIO/v1/session -H "Authorization: Bearer $KEY"

{ "state": "qr", "qr": "<PNG en base64>", "running": false }

state: loading → qr → connected. La primera vez el QR tarda unos 20 a 40 segundos. Al vincular, WhatsApp sincroniza ~45 segundos: antes de eso POST /v1/checks responde 409 session_syncing. Mostralo como data:image/png;base64,….

Formato de los números y normalización

Al conectar, GET /v1/session devuelve me: tu número vinculado, su país y un ejemplo de formato. Los números que envíes se normalizan automáticamente tomando ese número como referencia:

Podés indicar otro país con "country": "ES" o desactivar la normalización con "normalize": false. GET /v1/countries lista los países y POST /v1/normalize hace una vista previa sin gastar cupo y sin sesión conectada (si pasás country).

curl -X POST https://TU-DOMINIO/v1/normalize -H "Authorization: Bearer $KEY"   -d '{"numbers": ["1130633222", "011 15 3063-3222", "hola"], "country": "AR"}'

{ "country": "AR", "summary": { "total": 3, "valid": 1, "changed": 1, "invalid": 1, "duplicates": 1 },
  "examples": [ { "input": "1130633222", "phone": "5491130633222", "note": "se agregó el 9 de celular" } ],
  "invalid": [ { "input": "hola", "reason": "vacío" } ] }

3 · Verificar números

POST/v1/checks

curl -X POST https://TU-DOMINIO/v1/checks \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"numbers": ["5491122334455", "5492994713247"]}'

{ "id": "job_9a1c…", "status": "running", "total": 2, "truncated": false,
  "quota": { "limit": 50, "used": 0, "remaining": 50 } }

La respuesta incluye normalization (cuántos se corrigieron, repetidos e inválidos). Máximo 200 por pedido. Si pedís más de lo que te queda, se procesan los que alcanzan y truncated es true.

4 · Leer el resultado

GET/v1/checks/{id}   GET/v1/checks/{id}.csv

{ "id": "job_9a1c…", "status": "done", "total": 2, "done": 2,
  "yes": 1, "no": 1, "errors": 0,
  "results": [ { "phone": "5491122334455", "status": "no" },
               { "phone": "5492994713247", "input": "2994713247", "status": "yes" } ] }

input aparece cuando el número original se normalizó. El CSV lleva las columnas phone,status,input.

statusSignificado
yesEl número tiene WhatsApp.
noNo se encontró en WhatsApp (o está mal escrito).
errorNo se pudo comprobar (respuesta indeterminada); no descuenta del cupo. Trae detail.

Estado del pedido: running, done, stopped o error. Se consulta cada 1 o 2 segundos; cada número tarda ~1 s. Los resultados viven mientras la sesión esté abierta.

Uso responsable

Esta herramienta usa WhatsApp Web de forma no oficial. Usá una línea que no sea crítica y no verifiques listas enormes de golpe: WhatsApp puede restringir cuentas con patrones automáticos. Verificá solo números de personas con las que tengas una relación legítima.
